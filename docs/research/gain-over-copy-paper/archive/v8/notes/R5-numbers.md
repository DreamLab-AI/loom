## 1. Negative controls (§sec:controls, Table tab:controls, lines 393–431)

### 1.1 Reported quantities
- Original 4-arm cohort: n=57/arm (24 arcane + 33 thin), 1536-token budget, 36–50% empty-answer
  attrition (irrelevant 28/56=50.0%, true 24/56=42.9%, masked 23/56=41.1%, shuffled 20/56=35.7%,
  per v6 L206/v8 L253's rounder "36–50%").
- Rerun: 5 arms (+ fluent-noise), common retry policy (4096 tokens, 8192-token stragglers), 0%
  attrition, per-arm n≈50–55, re-judged from scratch by `gemini-3.1-pro-preview` on **both** old
  and new rows.
- Table `tab:controls`, 11 contrasts × 2 columns (old complete-case, new ITT) = 22 point
  estimates + 95% CIs, plus Holm-significance daggers on 3 of them (true−raw both columns,
  shuffled−raw ITT).

### 1.2 Earliest appearance and drift
- **The four-arm original design and the "true/shuffled/masked/irrelevant" harness**: introduced
  paper-v2, commit `48ed93a` (2026-08-17, "full experimental data — 360 judged answers, paired +
  control-contrast analysis") and `e140d34` (2026-08-17, "irrelevant-control donor must be
  seed-IRI-disjoint"). Surviving artefact: `uplift-results/paper-v2/control-results.jsonl`
  (228 rows = 57×4, verified by direct count in this session: `Counter({'true':57,'shuffled':57,
  'masked':57,'irrelevant':57})`), generated by `tools/paper/control_harness.py`
  (`ARMS = ("true","shuffled","masked","irrelevant")`, `MAX_TOKENS = 1536` hard-coded — confirmed
  by the prior R3 pass, §3 below, and independently re-checked by me).
- **First reported numbers** (paper-v4, `main.tex` L400–427, commit range up to `74952f9`/
  `919bd59`, 2026-08-22/23): a *complete-case-only* table with **different point estimates from
  every later version's "old (complete-case)" column**:
  - v4: true−raw `+0.59 [+0.16,+1.06]` p=0.026 n=32; irrelevant−raw `+0.04 [-0.54,+0.57]` p=0.73
    n=28; true−irrelevant `+0.35 [0.00,+0.78]` p=0.091 n=23; loom−true `-0.06 [-0.38,+0.25]`.
  - v5/v6/v8 "old (complete-case)" column (byte-identical across all three, first appearing in
    v5 commit `70bfec8`, 2026-08-24, "Technical Report v1 — reviewer-hardened restructure with
    three overnight studies"): true−raw `+0.78 [+0.31,+1.28]`; irrelevant−raw `+0.21
    [-0.29,+0.71]`; true−irrelevant `+0.30 [-0.22,+0.91]`; loom−true `-0.06 [-0.44,+0.31]`.
  - **This is a real, reader-visible drift, not just rounding**: same underlying 1536-token
    complete-case rows, different Δ and CI on every contrast (e.g. true−raw moves from +0.59 to
    +0.78, a 0.19 shift bigger than either CI half-width). The v5 prose explains the mechanism —
    "both the original complete-case rows and the new ITT rows were re-judged from scratch under a
    single judge, `gemini-3.1-pro-preview`... the original `gpt-4.1` figures are retained as
    historical context" (v8 L394) — i.e. v4's numbers are the **original `gpt-4.1`-judged**
    complete-case rows, v5–v8's "old" column is the **same rows re-judged by `gemini-3.1-pro-preview`**
    for judge-controlled comparability with the new ITT column. That is a defensible design choice,
    but the paper's table caption (L403–413) does not say the "old" column is a *re-judged* version
    of the v4 numbers, only that it is "the original complete-case rows" — a reader comparing v4's
    published abstract (+0.59) against v8's table (+0.78) with no access to the intermediate
    versions would see an unexplained change with no note that judge identity, not data, moved it.
  - The **rerun (ITT) column itself** — 4096/8192-token, 5-arm, 0%-attrition data — first appears
    complete, with the fluent-noise arm and all 11 contrasts at their final v8 values, in v5
    commit `70bfec8`. It has not changed in any digit from v5 → v6 → v8 (confirmed by diff of the
    three `tab:controls` blocks above).
- Two further textual variants worth flagging as drift, not number drift: v4's causal reading
  ("consistent with content-specific transfer... The content-specific residual is +0.35") is
  explicitly reversed in v5 onward ("we no longer read the verified-irrelevant arm as evidence of
  content-specific transfer, only as a correctly specified floor" — v5 L364, same sentence
  survives to v8 L398 in expanded form). The number didn't change generation-to-generation here;
  the *interpretation* of an already-published number did, tracking the newly added fluent-noise
  floor.

| **included** (in Table tab:controls) | Per-contrast n varies (paper states "per-arm n≈50–55" for ITT and per-contrast pairwise-complete sets for both columns) because each contrast uses its own pairwise-complete question set, explicitly **not reconcilable row-by-row** (paper's own admission, L400: "the table cannot be reconciled row by row"). | Same caveat; additionally the "common-intersection sensitivity analysis" the paper says it "owes" (repeat every contrast on the single question-ID set complete in all six arms) has not been run at all — stated directly in the paper (L400) and confirmed here: no such analysis file exists. |

**Why the sets could differ, from the record:** the paper attributes both the original attrition
and its cause (reasoning-budget exhaustion: "the backend emitting a reasoning block before its
answer so that at 1536 tokens the reasoning alone consumed the budget," L394) directly to a
per-question, per-arm interaction between scaffold length/disorder and the fixed token budget —
longer or more disordered scaffolds provoked longer reasoning traces, which more often blew the
1536-token cap before the answer was written. That is a documented, plausible mechanism for
*why* per-arm completed-n varied in the original cohort (it is visible in the attrition-rate
spread, 35.7–50.0%, correlating loosely with which arms carry more/less scaffold text). It does
**not** explain the ITT cohort's per-contrast n variation, because that data was never written to
disk — the paper's "pairwise-complete set differs per contrast" claim for the rerun is therefore
**not currently checkable**, and this is the one cell of the table that must be stated as
underivable outright: **there is no way, from anything in this repository, to confirm which
question IDs survived into each of the eleven ITT contrasts, or why they differ from one another.**
The two candidate explanations the task prompt raises (arms run on subsets; graded rows dropped;
raw arm reused from Study 2) are all *consistent* with the prose but none is confirmable: Study 2's
raw arm is a plausible reuse candidate given "the four negative-control arms... use the same node"
and "the raw arm calls the same backend without a scaffold" (§sec:method L244), which is
structurally identical to Study 2's own raw arm — but the paper never states outright that the
control rerun's raw-arm rows *are* Study 2's raw rows reused rather than freshly generated, and no
row-level provenance field would let you tell the two apart even if the data existed.

## 2. Composition (§sec:composition, §sec:gemma, figures/fig-composition.tex)

### 2.1 Reported quantities
- Corpus: 6,514 qualifying two-edge chains mined, 150 sampled across 4 relation-pair shapes, over
  `requires`/`hasPart` restriction-encoded relations.
- 6 arms (both / a-only / b-only / masked / irrelevant / raw) × 12 models.
- Per-model both-premises recall, b-only recall, and Δ=both−b-only with bootstrap 95% CI
  (plotted, not tabulated, in `fig-composition.tex`).
- Named deltas in prose: Gemini 3 Flash +0.33, Qwen3.8-27B (local) +0.29, DeepSeek v4 +0.26,
  Sonnet 5 +0.25, Opus 4.8 +0.20 (composers); GPT-5.6, GLM-5.3, Haiku 4.5 (null, CI spans 0);
  GPT-4.1-mini −0.47, Mistral-24B −0.29, GLM-4.7 −0.18, Llama-70B −0.12 (anti-composers).
- b-only range 0.31–0.89; masked recall ≤0.61 (most <0.2); control arms (a-only, irrelevant, raw)
  at floor, ≤2/150 for every model; 99.97% of naively mined chains failed eligibility filters.
- Gemma replication (§sec:gemma): composition Δ=+0.693 [+0.613,+0.767], b-only recall 0.260;
  sweep raw recall 0.099 → scaffold recall 0.938 against ceiling 0.964, gain −0.027
  [−0.037,−0.018].

  local Qwen, 3 null incl. GPT-5.6, 4 anti-composers)" — matching v8's group sizes (5/3/4) exactly.
  The 6,514-chain corpus size and 99.97% filter-failure rate both first appear in this same

### 2.4 Recomputability
**Not recomputable from released inputs**, in whole. The only thing a reader can check
independently is (a) that the four named anti-composer deltas match the plotted figure
coordinates (internal consistency only), and (b) that the copy ceiling quoted for Gemma (0.964)

## 3. Paraphrase / vocabulary mismatch (§sec:paraphrase)

### 3.1 Reported quantities
- Stress-set: all 510 sweep questions rewritten by an LLM, leak-checked (0/510 contain a title
  token), graded for resolvability by two model families (69% resolvable by at least one).
- Ceiling collapse: mean 0.96 → 0.34; 62% of questions below 0.5.
- Fallback engagement: fires on only 3/510 (designed absence-keyed gate is inert).
- Semantic-only arm (top-5 cosine over all 8,146 class embeddings): ceiling recovery +0.42
  [+0.38,+0.47] on the failing 62%.
- Naive union arm: recovers "only a third of that" (not independently numbered).
- Generation-side check, stratified 100-question pass: semantic-only answer recall +0.221
  [+0.118,+0.323] (recall 0.10→0.32) on the crossover (ceiling<0.5, 62% of set); naive-union gain
  +0.030 (CI includes zero); semantic-only's exposure-to-delivery gap −0.145 on the crossover.

### 3.2 Earliest appearance
- The 0.96→0.34 collapse and the 62% figure first appear, word-for-word ("0.96 on the original
  questions to 0.34 on the paraphrases, with 62% of questions below 0.5"), in **paper-v4**
  (`main.tex` L675, part of commit `74952f9`'s companion pass or an adjacent commit in the same
  window — confirmed present already by v4; `git log -S"0.34 on the paraphrases"` on
  `docs/research` shows the string only added in the v8 commit for *that path*, because each
  `paper-vN/main.tex` is a distinct file, but manual grep of v4/v5/v6 above confirms the identical
  sentence is present unchanged in all four versions). The commit message of `70bfec8`
  (v5, 2026-08-24) explicitly claims this study as new-in-that-drop: "Vocabulary mismatch:
  exposure collapse 0.96->0.34; absence-keyed fallback structurally blind (fires 3/510);
  semantic-only recovers +0.42 ceiling and +0.22 delivered recall on the failing 62%; naive union
  loses half to budget crowd-out" — but the 0.96→0.34 sentence is already present in v4's
  `main.tex`, so the commit message overstates novelty for that specific number: the collapse
  figure predates v5, only the semantic-only-arm and generation-side-check figures (+0.42, +0.221)
  are new in v5.
- **No drift**: 0.96→0.34, 62%, 3/510, +0.42 [+0.38,+0.47], and the generation-pass +0.221
  [+0.118,+0.323] are identical, digit for digit, across v4/v5/v6/v8 wherever each first appears.

### 3.3 Surviving computation output
- **None.** No file matching `*paraphrase*`, `*stress*question*`, or `*vocab*mismatch*` exists
  anywhere in the repository (checked by filename search across the full tree). There is no
  510-question paraphrase set, no per-question ceiling-before/after pair, no semantic-only or
  naive-union per-model row, and no 100-question generation-pass row file.
- The paper states this explicitly and consistently: v8 L235 ("the paraphrase stress-set behind
  the 0.96-to-0.34 collapse, and the per-arm ceilings computed on it, are reported but not yet
  released") and L64 item (vi) ("The paraphrase stress-set of §sec:paraphrase and its per-arm
  ceilings are likewise not released").
- The **only artefact that indirectly bears on the study** is `uplift-results/questions.jsonl`
  (the *original*, non-paraphrased 510-question set that the stress-set was built by rewriting) —
  useful only in that it fixes what "0.96" (the un-paraphrased mean ceiling, ≈ the sweep's 0.9645
  macro ceiling from `decomposition.json`) is being compared against, not as evidence for the
  0.34 figure itself, which requires the unreleased rewritten questions.

### 3.4 Recomputability
**Not recomputable.** Even the matcher and scaffold engine used (`tools/paper/
decompose_exposure.py`, `ontology_scaffold_v1.py`) are released and would let a reader reproduce
the *method*, but not the *numbers*, because the input (the 510 paraphrased questions and which
model(s) generated/graded resolvability) is not released and the paper does not name the
paraphrasing model or prompt in enough detail to regenerate an equivalent set deterministically
(no seed, no exact prompt template given in `main.tex`).

## 4. Semantic re-score (§sec:rescore)

### 4.1 Reported quantities
- Thresholds 0.80/0.85/0.90; ceiling at 0.80/0.85 = 0.980/0.968 vs 0.964 lexical; at 0.90 both
  recall and ceiling fall below lexical values.
- All 30 model×threshold gain-over-copy combinations negative, CI excluding zero.
- Pooled n01 (unexposed-yet-recovered) stays low single digits at every threshold: 3/11,360 at
  0.85; largest single-model count at any threshold is 4.
- Qwen-2.5-72B: −0.050 lexical → −0.034 at 0.80 (largest per-model shift).

### 4.2 Earliest appearance
- Commit `9ef671e` (2026-08-23, "paper-v4 + artifacts: semantic re-score kills the
  lexical-matching critique"). All headline numbers (0.980/0.968 vs 0.964, 30/30 CIs excluding
  zero, n01=3/11,360 at 0.85, max single-model n01=4, Qwen-2.5-72B −0.050→−0.034) are present
  **unchanged** from this commit through v8; v5/v6 report the same figures with progressively more
  qualified prose (v5 L137 gives only the coarse 0.980/0.968-vs-0.964 summary; v6 L142 and v8 L190
  add the full per-threshold breakdown and the n01=3/four-max detail). This is prose elaboration,
  not number drift.

### 4.3 Surviving computation output
- **Script released, saved results not.** `uplift-results/semantic-rescore/` contains exactly two
  tracked files:
  - `rescore.py` (10,734 bytes) — the re-scoring script itself: loads
    `uplift-results/sweep/results-{model}-scaffold.jsonl` (the same Study 1 sweep rows used
    throughout) and `uplift-results/questions.jsonl`; re-embeds candidate spans with
    `bge-small-en-v1.5` via the Xinference endpoint at `192.168.2.132:9997`; regenerates the copy
    contexts byte-identically via `ontology_scaffold_v1.py` (not stored per-row in the sweep) and
    scores both context and answers with the same embedding matcher for symmetry; sweeps
    thresholds 0.80/0.85/0.90 with a seeded (42) 10,000-resample paired bootstrap. The script
    imports `embed_lib.py`, which is **not present** in the directory (referenced but absent —
    confirmed by directory listing).
  - `RESCORE.md` (8,355 bytes) — a **prose report of the script's output**, including a full
    per-model table (lexical R/C/G vs sem@0.80/0.85/0.90 R/C/G [CI]) that matches the paper's
    Table/text numbers exactly (spot-checked: Qwen-2.5-72B row gives `.914/.965/-.050` lexical and
    `.946/.980/-.034 [-.046,-.022]` at 0.80 — matching the paper's "-0.050 lexical to -0.034 at
    0.80" exactly), plus the n01 decomposition table (n01=3 pooled at 0.85, matching the paper).
  - **What is missing**: `rescore_results.json` (the machine-readable per-question/per-model
    output), `embed_cache.json` (the 274,616-vector embedding cache RESCORE.md itself says "is
    left in this directory for reproducibility/audit" — it is not; only `RESCORE.md` and
    `rescore.py` are present), and `embed_lib.py` (imported by `rescore.py` but absent). This
    matches the paper's own disclosure (v8 L64 item iii: "The semantic re-score of §sec:rescore
    releases its script but not its saved results or embedding cache, so its table can be
    re-derived only by re-running the embedding endpoint") and the prior remediation pass's
    finding (`REMEDIATION-2026-09-21.md` L354: "`rescore_results.json`, `embed_cache.json` and the
    imported `embed_lib.py` are all absent; only `rescore.py` and `RESCORE.md` are released").
- **RESCORE.md is therefore the nearest thing to a surviving computation output** — it is a
  narrative artefact written by whoever ran the (now-unrerunnable-as-is, since `embed_lib.py` is
  gone) script, not the raw machine output, but its per-model table is precise to 3 dp and
  internally consistent with both `rescore.py`'s documented method and the paper's published
  numbers. I treat it as **surviving computation output in prose form**, distinct from a
  regenerable JSON artefact.

### 4.4 Recomputability
**Partly.** The Study 1 sweep rows it re-scores (`uplift-results/sweep/*`) are released and
byte-stable (confirmed against `sweep-analysis.md`, §5 below), and `rescore.py` documents its
method precisely enough to re-implement — but it cannot currently be *re-run as released* because
`embed_lib.py` (containing `EmbedCache`, `cosine`, `extract_candidates`, `normalise_title`) is
missing, and the embedding cache that would make re-running cheap is also missing. A reader with
access to the live `bge-small-en-v1.5` endpoint at `192.168.2.132:9997` and willing to
reconstruct `embed_lib.py` from `rescore.py`'s calling conventions could regenerate the numbers
from scratch; nobody can currently just re-run the released files as-is.

## 5. Shared dependency: the 0.964 copy ceiling and Study 1 sweep rows

All four sections above lean on the model-independent 0.964 copy ceiling and the ten-model sweep
recall/uplift numbers from §sec:tenmodel (Table `tab:sweep`). This **is** fully recomputable and
independently verified in this session:
- `uplift-results/sweep/` contains per-model raw and scaffold JSONL rows
  (`results-{model}-{raw,scaffold}.jsonl`), plus `scores-*-summary.json` and
  `sweep-analysis.{md,json}`.
- `uplift-results/sweep/sweep-analysis.md` reproduces Table `tab:sweep` to 3 dp exactly, including
  the domain-clustered CIs, truncation counts (GLM-4.6 174/5, Gemini-2.5-Flash-Lite 16/0), and the
  0.964 ceiling constant across all ten rows.
- `uplift-results/paper-v2/DECOMPOSITION-SUMMARY.md` + `uplift-results/paper-v2/decomposition.json`
  independently reproduce the n11/n10/n01/n00 decomposition (pooled n01=3, n10=735) that both
  §sec:controls' framing sentence and the composition section's opening reference ("beyond-exposure
  recovery in only 3 of 11,360 gold items") depend on. A prior researcher pass
  (`docs/research/paper-v8/notes/R3-data.md` §1–2) independently re-derived these same numbers
  from the raw sweep rows in a fresh session and confirmed exact agreement (0.933099 pooled,
  0.964477 macro rounding to the paper's 0.964, n01=3 exactly), and additionally found a small,
  disclosed-worthy refinement: the paper's "1 in 14" exposed-item-drop rate (735/10,600) becomes
  "1 in 15.5" (683/10,600) once 52 "any"-type compliant omissions are excluded — the paper's own
  v8 text (L264) already incorporates this correction verbatim, so it is resolved, not open.

This shared foundation is solid; the provenance problem is specific to the four newer instruments
(control rerun, composition, paraphrase stress-set, and — to a lesser, script-preserved degree —
the semantic re-score), all of which post-date the original Study 1/2 apparatus and were run and
reported without the per-row logging discipline that Study 1/2 already had.
