## Divergences from `loom_graph.py` (Python semantics win; noted where refined)

1. **Empty-store availability.** Python creates the `Store` unconditionally, so a dir
   with no allowlisted file reports `available=true, triples=0`. We report
   `available=false` with an explanatory `status().error` — the honest /health signal for
   fail-open (a graph with zero published triples is not a usable read-truth). Load
   failure / parse error behaves identically to Python (store=None, available=false).
2. **`_term_str` → typed matching.** Python string-strips `<iri>` / `"v"^^<t>` / `"v"@lang`
   via regex on `str(term)`. We match typed `oxigraph::model::Term`: `NamedNode → as_str()`,
   `Literal → value()`, blank/quoted → `Display`. Same output, no regex.
3. **`SparqlResult` is positional, not dict-keyed.** The domain type is
   `{columns, rows: Vec<Vec<String>>, boolean, truncated}`. SELECT rows are emitted in
   column order (unbound var → empty string, vs Python's `None`/absent key). CONSTRUCT/
   DESCRIBE (`QueryResults::Graph`) emit a single `"triple"` column of the N-Triples string,
   matching Python's `{"triple": str(tr)}` shape.
4. **`search_labels` projects `?p`.** The Python query selected only `?s ?label`; we also
   project `?p` (WHERE identical) to populate the typed `LabelHit.predicate`. Empty needle
   → `LoomError::BadQuery("empty query")` (Python returned an error dict).
5. **Query-execution errors → `BadQuery`.** Python distinguished `bad_query` (validation)
   from `query_failed` (runtime). The domain has one 400-mapped `BadQuery`; both collapse
   into it (runtime SPARQL failure is query-caused). Validation vs execution detail is
   preserved in the error string.
6. **Unparseable `LOOM_SPARQL_LIMIT`/`LOOM_SPARQL_MAX_ROWS` → default** (Python would raise
   at import). No panic; falls back to 10000.

The `_FORBIDDEN` / `_READ_FORM` / `_LIMIT_RE` regexes and the `_clamp` LIMIT-injection
(anchored `^\s*SELECT`, `.rstrip().rstrip(";")`, `\nLIMIT n`) are carried verbatim.
