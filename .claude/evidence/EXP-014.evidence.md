# EXP-014 — F3 thinking + budget control

**Verdict: PASS (with audit remediation).** For engaged (scaffold-injected)
delegations only: `LOOM_BACKEND_NO_THINK=1` adds
`chat_template_kwargs:{"enable_thinking":false}` when the client did not set it;
`LOOM_THINK_TOKEN_FLOOR` raises a sub-floor integer `max_tokens` when thinking
stays active. Both default OFF — current behaviour preserved exactly.

- date (UTC): 2026-08-18
- base git SHA: 328f697 (pre-commit working tree)
- crates touched: loom-facade (`serving.rs`, `routes.rs`, `config.rs`), loom-backend-openai (`raise_integer_token_floor`)

## Design decisions
- **Shared integer floor primitive.** `LOOM_THINK_TOKEN_FLOOR` reuses the backend
  adapter's audited integer-only floor logic, extracted as the public
  `raise_integer_token_floor(map, floor) -> bool` (single-sourced from the
  `LOOM_MIN_MAX_TOKENS` audit-finding-2 remediation): only serde integers are
  raised (negatives too, via `max(v, floor)`), higher asks / strings / floats /
  overflow / null pass through verbatim, no key is inserted.
- **Engaged-only.** No-think kwargs and the think floor are applied ONLY on an
  engaged delegation; a passthrough (non-injected) request is never touched.
- **AUDIT REMEDIATION (finding 1 — High): default floor is 0, NOT 1536.** The
  original default of 1536 would re-floor engaged requests even with F3
  unconfigured, changing behaviour for a deployment that had disabled the backend
  floor (`LOOM_MIN_MAX_TOKENS=0`). Fixed to default 0 (F3 fully off ⇒ backend's
  `LOOM_MIN_MAX_TOKENS` is the sole floor, current behaviour EXACT). Profile A sets
  `LOOM_THINK_TOKEN_FLOOR=1536` explicitly — matching the `LOOM_MIN_MAX_TOKENS`
  default it also runs, so the think-active path never truncates. Regression test
  `f3_default_off_leaves_engaged_max_tokens_untouched` added.
